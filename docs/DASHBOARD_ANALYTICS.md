# 经营概览统计说明

## 日期范围

默认近30天，提供今天、近7天、近30天、本月及自定义日期。均以北京时间下单日期归属订单，包含首尾日期，最长366天，禁止未来日期或结束早于开始。后端使用左闭右开的UTC边界，不从前端分页订单列表计算总额。

## 收入与退款

- 实付金额：期间下单、已完成支付的订单总金额，含运费和优惠后金额；包含当前 PAID、REFUNDING、REFUNDED 状态。
- 成功退款：上述订单截至查询时所有 SUCCEEDED 退款金额之和；多个退款先按订单合计，避免重复累计成交额。
- 退款后净收入 = 实付金额 − 成功退款金额。申请中、审核通过处理中、失败或拒绝退款不扣减。
- 这是订单归属期间的当前净收入，不是期间到账流水，也不扣采购、物流、平台手续费等成本，不代表利润。之后退款成功时，原下单日期的净收入会随之更新。
- 已支付订单数量含全额退款订单；每日趋势补齐没有销售的日期，明细可展开查看实付、退款、净收入和订单数。

## 期间复购率

按正式用户 openid 去重；期间内已付款且扣成功退款后剩余金额大于0的订单视为有效订单。至少有2笔有效订单的用户为复购买家，期间复购率 = 复购买家数 / 有效买家数。部分退款保留，全额退款排除，没有有效买家时显示“—”。这是期间内重复购买比例，不是依据全部历史购买判断的老客占比或留存率。演示模式用明确的虚拟买家ID，同样执行统计逻辑。

## 订单转化漏斗

按同一批期间下单订单计算：提交订单 → 完成支付 → 确认收货。已支付订单在退款后仍保留“曾完成支付”计数；确认收货以 fulfillment_status=RECEIVED 为准。每一步显示相对于上一步的转化率，上一步为0时显示“—”。取消和超时关闭订单仍计入下单分母。此漏斗保持按订单计数，包含直接购买，与访问漏斗的人数分别统计。

## 访问与加购转化漏斗

新增「访问小程序 → 加入购物袋 → 提交订单 → 完成支付 → 确认收货」，各阶段按登录用户去重，不用订单数除以访客人数。

- 小程序每次进入前台调用 `analytics.visit`；服务器按北京时间日期和认证 OpenID 唯一保存当日首次访问时间，重试或多次打开不增加人数。上报失败不影响浏览。
- 商品页成功加入购物袋携带 `addToCart: true`，后端在购物袋写入成功后记录首次加购时间，并补齐访问记录。数量编辑、勾选、删除、失败加购及直接购买不记录加购。记录失败写服务日志，不影响购物袋操作。
- 同一查询期间内访问过的用户构成起点；加购必须在期间内，下单必须在该用户期间首次加购之后且在结束边界之前。下游付款和收货按这些订单当前状态判断。每位用户每阶段计一次，重复订单不增加人数。支付含退款后曾支付订单。
- 日期仍使用北京时间、包含首尾日期。分母为0显示「—」。历史访问和加购不回填；采集开始时间由迁移保存，重复迁移不重置。范围包含采集前时段时显示覆盖提示。无访问时展示空状态和0人。
- 仅返回聚合计数，不返回 OpenID。当前采集限已登录小程序用户；不覆盖其他渠道、未成功上报或旧版小程序。漏斗表示用户购物袋路径，不做逐商品或会话归因。匿名访问不在范围内。
- 演示后台使用独立且明确标注的虚拟访问/加购样本；小程序演示记录存在本地，两端演示存储不互通。

## 待办与权限

待发货、待审核退款、新合作线索均为当前全部待办，不受日期筛选影响。部分退款且仍可发货的订单纳入待发货数量。最近订单和渠道机会同样保持最新数据，页面标注独立范围；只有具有 order.read / lead.read 权限的管理员才请求并展示相应详情。经营汇总继续使用 dashboard.read 权限，不返回用户标识。

筛选加载期间展示更新状态，出错隐藏旧统计并支持重试，旧请求不能覆盖新结果。正式接口所有统计查询共享只读可重复读事务快照。

## 发布与验证

先执行 `backend/migrations/20261008_commerce_analytics.sql`（新库 schema 已包含），再同步发布后端、小程序及后台。新增 commerce_activity 与 commerce_analytics_state 两表，不补录历史。数据库日期沿用现有UTC存储约定。正式数据上线前应对照实际订单及成功退款明细核对金额；本地验证未连接生产MySQL。

- `node tests/commerce-analytics.cjs`：小程序前台访问、成功加购、重复去重及购物袋编辑隔离。
- `npm run test:dashboard`：日期、退款金额、复购、漏斗、每日总额、空数据、请求时序、失败重试及权限隔离。
- `npm run admin:build`：后台类型检查和构建。
- 在 backend 运行 `go test ./...`：含日期边界、事务快照、汇总和失败回滚测试。
- 启动演示后台 `npm --workspace admin run dev -- --host 127.0.0.1 --port 5186` 后，运行 `npm run test:dashboard-ui`。可通过 ADMIN_UI_URL 改变地址，通过 PLAYWRIGHT_BROWSER 指定浏览器。覆盖登录、自定义日期、收入、复购、漏斗、每日明细、空状态、待办、非法范围及恢复；截图保存于 tests/artifacts/dashboard-1360.png。

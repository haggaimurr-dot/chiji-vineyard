# 商品评价：晒图、追评、评价审核、商家回复

小程序在订单详情确认收货后评价商品。首次评价填写1–5星和1–500字内容，可选最多6张图片；每张压缩后不超过512KB，支持JPEG、PNG、WebP。文字、图片及商家回复在评价审核通过后公开匿名展示，表单提示不要上传个人信息。

首次评价成功后，订单详情入口变为「追加评价」，追评填写1–500字内容，可再附最多6张图片。每条评价只允许追评一次，保留原评分、原文字与晒图，不增加评价总数，也不改变平均评分。已追评入口禁用。评价加载失败时可重试，提交失败保留文字与所选图片。

商品详情按原评价时间分页，展示首次晒图、追评内容与图片、追评时间、商家回复与时间。图片可点击放大。订单详情可查看自己的评价、追评及回复。

后台「商品评价」按20条分页展示评价，运营人员和超级管理员均可发布1–500字商家回复。每条评价只能回复一次，已发布后展示正文与时间，失败保留草稿。正式回复记录操作日志。回复与追评使用数据库行锁串行更新，互不覆盖；用户只能追评自己的评价。

## 评价审核

后台「商品评价」支持按全部、待审核、已通过、已驳回筛选，保留20条分页。新评价进入待审核；提交追评后整条评价重新进入待审核，审核期间原评价、追评及回复均暂不公开。运营人员与超级管理员可审核通过或驳回，驳回须填写1–500字原因；已通过评价可驳回下架，已驳回评价可重新通过。每次审核记录时间及操作日志。

商品详情列表、评价总数和平均评分仅包含已通过评价。订单详情仍向买家本人显示待审核、已驳回的内容及驳回原因。商家可先回复待审核评价，回复随评价审核通过后展示；回复仅允许一次，失败保留草稿。审核、追评和回复共用评价行锁，保留彼此内容。

审核状态、驳回原因及审核时间保存在现有 `review_details.payload` 中，无需新增数据库字段。未存审核状态的历史评价按已通过处理，不会自动隐藏。演示模式遵循相同展示规则，但小程序新评价无法通过独立的后台演示存储审核，跨端审核验收需使用同一真实后端。

## 上线步骤

1. 已有数据库执行 `backend/schema.sql` 中的 `CREATE TABLE IF NOT EXISTS review_details` 语句。原 `product_reviews` 数据无需修改，仍可展示并追评/回复。
2. 配置 `PUBLIC_BASE_URL` 为后端公开的HTTPS地址。晒图随评价提交，后端验证图片类型与大小，再在同一事务中写入 `media` 和评价详情；失败整体回滚。
3. 在微信小程序后台配置该HTTPS图片域名供图片显示和预览，发布后端、后台及小程序，修改TypeScript后运行 `npm run mini:build`。
4. 真机验证相册/拍照、压缩后体积、图片展示与放大，以及两端连接同一后端时商家回复回显。

演示模式中，小程序图片保存为用户目录本地文件，评价与追评保存于微信本地存储。后台演示评价与回复保存于浏览器本地存储。两端演示数据各自独立，跨端联调须连接真实后端。

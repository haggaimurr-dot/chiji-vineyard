# 葡萄园小游戏第一版实现与验收

日期：2026-10-12。

用户确定的产品形态是“葡萄园小程序跳转独立微信小游戏”。本版建立独立小游戏工程、独立身份和游戏账本，复用现有 Go / MySQL；商城只增加入口。

## 实现内容

| 部分 | 本版行为 |
| --- | --- |
| 场景 | Canvas 2D 手绘等距葡萄园，四个可选择的已成园地块 |
| 时间 | 84 个模拟日，回合推进 7 日，离线按现实小时补算 |
| 农事 | 灌溉、施肥、整枝通风、疏果控产、巡园防护、采收，带窗口、冷却和经营币成本 |
| 模型 | 土壤水分、养分、冠层、留果负载、树势、粒重、糖度、损伤与确定性天气 |
| 经营 | 采收等级、鲜果库存、采后损耗、批发/零售、收入和成本 |
| 设施 | 滴灌、避雨、小型冷库，作用与维护费用各不相同 |
| 持续经营 | 一季复盘，下一季保留资产、设施和树势 |
| 演示模式 | 本机持久化，读写失败明确提示，确认后重开，不静默丢弃损坏存档 |
| 正式服务 | 独立 game 会话、服务端计算、MySQL 存档和命令防重 |
| 商城入口 | 首页“模拟种植”、个人页“我的葡萄园”，配置真实小游戏 AppID 后跳转 |

此前调研推荐 Cocos 作为长期场景制作方案。本次环境未找到可用的 Cocos 编辑器，首版采用微信原生 Canvas 2D，使小游戏工程可以直接运行和验证；画面、农艺模型和服务接口保持分离。

## 文件与启动

小游戏目录：[minigame](../minigame/README.md)。

试玩：仓库根目录运行 npm run game:build，再运行 npm run game:preview，打开 [本机试玩](http://127.0.0.1:5199)。

微信运行：导入 minigame 目录，填写真实小游戏 AppID。商城跳转配置位于 [小游戏入口配置](../miniprogram/data/vineyard-game.ts)。

正式服务：部署 Go 服务，执行 [游戏数据库迁移](../backend/migrations/20261012_vineyard_game.sql)，配置小游戏专用 AppID/Secret 与 HTTPS 地址，再将游戏 demo 改为 false。具体步骤见 [小游戏说明](../minigame/README.md)。

## 验证依据

- 种植模型测试：完整季、农艺权衡、非法窗口与余额、库存守恒、保鲜损耗、离线分段一致、纯函数、损坏存档及基本回合玩法。
- 请求与存档测试：持久化、存储失败、旧版本冲突、网络丢响应防重、跨重启恢复、不确定服务器响应与正式模式不降级。
- 原生 API 模拟：无 DOM 启动、DPR/安全区、触摸执行一次、禁用操作、回合确认、后台暂停和恢复及监听释放。
- 小程序入口测试：未配置、正常跳转、取消、失败重试、防重复和传值范围。
- Go 模型与四个 JavaScript 样本进行完整状态对比，核对线上正式计算和演示计算一致。
- 后端检查包括独立会话、请求防重、参数校验、事务回滚、重开隔离、全量测试和静态检查。
- 浏览器完整操作与视觉测试的截图和结果保存到 docs/test-evidence/2026-10-12-vineyard-game；该验证不能代替微信真机。

实际结果：10 项模型测试、12 项请求与存档测试、原生 API 模拟及小程序入口测试通过；浏览器覆盖 10 组流程、36 类控件状态，产出 11 张截图，无页面异常。Go 全量测试和静态检查通过，四个跨语言状态样本完全一致。

真实 MySQL 8.4.11 的并发验收通过：12 个会话同时初始化只产生一份存档，重复请求只扣费一次，并发版本争用只接受一个动作，重开与操作竞争保持递增版本。测试使用独立临时库并在结束后清理。根据该验证，初始化使用不覆盖状态的重复键更新先取得排他锁，避免共享锁升级造成死锁。

## 实际边界

当前未提供真实小游戏 AppID / AppSecret。默认演示可以运行，商城入口尚未开放真实跳转，正式微信登录和公开发布尚需相应环境。

模型参数用于教学与可玩性；尚未按真实产区、品种和生产记录校准。首版没有两端账号绑定、真实商品兑换、支付、多人联机或 Cocos 工程。

服务器只保留每个用户自己的游戏数据；游戏状态、虚拟资产和商城交易隔离。重开游戏只修改该用户的游戏存档和命令，不操作商城订单或实际库存。

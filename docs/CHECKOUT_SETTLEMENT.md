# 订单与优惠结算：幂等下单、复杂配送

## 使用

小程序自动为一次结算生成 `idempotencyKey`，网络失败重试沿用同一个键。商品数量、收货资料、优惠码、日期或备注改变时生成新键；客户端传入的商品价格和展示快照不参与幂等校验，价格仍从服务端读取。

同一用户、同一键、相同内容只生成一张订单，库存预占、优惠券占用及购物袋移除只执行一次。同键提交不同内容报错。不同用户的键互不影响。失败事务同时回滚键和订单，可以继续重试；已成功的键永久关联原订单，即使原订单已付款、关闭或取消也返回原订单，新购买必须使用新键。

下单成功后支付取消或失败会进入该订单详情。下单响应丢失时本地保留尝试键；重新打开结算先调用 `order.recover` 查询当前用户的原订单，避免被已占用的券或已扣减的库存阻挡。找不到时继续原结算；恢复查询失败保留键并提供重新加载入口。

后台「运营配置 → 运费规则」可添加区域规则，沿用配置版本、回滚及操作日志。

- 地区名称精确匹配地址中的省、市、区县；区县规则优先于城市，城市优先于省，同一地区不可重复。未匹配使用原统一运费。
- 省级禁售名单始终优先；区域暂停配送使用最具体的规则，允许为较大区域设置局部例外。
- 区域规则包含基础运费、包含件数、每超出一件运费、独立包邮门槛和地区附加费。件数为整单所有规格的购买数量之和，不是箱数或重量。
- 优惠前商品金额达到门槛免基础及续件费，地区附加费仍收取。门槛为0表示始终免基础及续件费。券不抵运费，商品应付至少1分。
- 暂停配送日期使用北京时间 `YYYY-MM-DD`，报价显示拦截原因，创建订单再次校验。仍支持两天后至30天内的期望日期，预售不得早于预计发货日期；「尽快配送」由商家安排可配送日期，期望日期不保证送达。

例如：基础运费10元含2件，超出每件2元，包邮门槛200元，地区附加费4元。3件商品金额150元时运费16元；商品金额300元时运费4元，优惠券减额不改变这个包邮结果。

## 接口与上线

`order.create` 必须携带16至80位的 `idempotencyKey`，允许字母、数字、下划线、连字符。旧客户端不带键会被拒绝，需协调发布。`order.recover` 接收 `{idempotencyKey}`，仅返回登录用户关联订单，无记录返回 `null`。`order.quote` 增加 `deliveryDate`，响应增加匹配规则名称 `shippingRuleName`、附加费 `surcharge`、可选日期边界 `deliveryMin` / `deliveryMax`；`freight` 已包含附加费。

配送配置可增加 `regions` 与 `blockedDates`。每条区域规则字段为 `name, province, city, district, blocked, freight, freeShippingThreshold, baseQuantity, extraFreight, surcharge`，金额单位为分，市／区未指定时用空字符串。最多100个区域和366个日期；旧配置无需转换。

上线前先执行 [schema.sql](../backend/schema.sql) 末尾的 `order_idempotency` 建表语句，再协调发布后端、小程序与后台。键区分大小写；不要删除已成功的关联记录，否则旧请求重放可能重复下单。无需修改原 orders 表。

小程序演示配置独立于后台演示配置，默认沿用原运费；示例订单在当前设备保存，幂等及恢复行为与正式接口一致，不代表真实数据库并发或支付验收。

## 验证

`npm run test:checkout` 验证演示并发重试、同键冲突、券占用、丢响应恢复、支付取消、区域优先级、包邮附加费与配置校验。后端运行 `go test -run 'TestCheckoutIdempotencyTransactions|TestComplexDeliveryRules|TestConfig' ./...`，使用数据库驱动夹具验证事务回滚、8个并发调用只生成一张订单、用户隔离及日期／优惠边界。上线仍须在实际 MySQL 环境验收并发及回滚。

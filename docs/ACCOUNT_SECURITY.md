# 登录与个人账号安全

后台所有启用的管理员账号（含无业务权限的运营人员）都能通过「账号安全」管理自己的密码和多因素认证。账号管理中的超级管理员重置密码功能继续保留。

## 修改自己的密码

输入原密码、新密码及确认密码。新密码要求 10–128 个字符，不能与原密码相同。后端仅修改当前会话所属账号，忽略客户端传入的其他账号 ID。启用多因素认证时还需验证动态码或恢复码。修改成功后所有旧登录会话失效，返回登录页。

## 多因素认证

1. 输入原密码并点击「绑定验证器」。在验证器中手动添加基于时间的账号，填入页面显示的密钥。
2. 输入验证器的 6 位动态码并点击「验证并启用」。未完成验证的绑定不会启用认证；绑定密钥 10 分钟后过期。
3. 保存一次性展示的 8 个恢复码，再重新登录。认证开关会使所有旧登录会话失效。
4. 登录先验证账号密码，再要求动态码或恢复码；第二步完成前不会签发登录令牌。动态码使用后不能在同一个时间步重复使用，绑定用过的动态码也需要等待下一次刷新。
5. 验证器丢失时，可使用恢复码登录。每个恢复码只能使用一次；在账号安全页使用另一个恢复码关闭认证后，可以重新绑定并获得新的恢复码。

采用 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) 的 TOTP：HMAC-SHA1、6 位、30 秒周期，允许相邻一个时间步的时钟偏差。后台按账号串行锁定并原子消费动态码/恢复码，支持多实例；登录和个人安全操作都有数据库限流。

## 数据与部署

- 新安装使用 `backend/schema.sql`；已有数据库在发布后端前执行 `backend/migrations/20261006_account_security.sql`，新增 `admin_security` 表。默认全部账号保持未启用状态。
- 生产密钥由 `TOKEN_SECRET` 分离派生后用 AES-GCM 加密，密文绑定账号 ID；恢复码只存摘要。保持此配置稳定，更换 `TOKEN_SECRET` 会使既有验证器密文无法解密，应在更换前安排关闭并重新绑定认证。
- 密码修改、绑定、启用和关闭操作及其审计记录在同一数据库事务提交。审计失败会回滚密码、安全状态与恢复码消费。审计内容不记录密码、密钥、动态码或恢复码。
- 管理接口响应使用 `Cache-Control: no-store`。绑定密钥和恢复码不保存到前端本地存储；恢复码展示在登录页内存中，刷新后无法再次查看。
- 演示模式在浏览器会话中模拟同样流程，首次登录记录输入密码的摘要，之后需使用该密码；验证器演示密钥存于本地会话状态，仅用于预览。

## 验证

`cd backend && go test ./...`：标准测试向量、密文账号绑定、原密码与新密码校验、账号隔离、会话撤销、密码登录不绕过第二因素、绑定过期、动态码重放、恢复码一次性消费及事务回滚。

`npm run test:account-security`：无业务权限运营人员修改密码，以及演示绑定、第二步登录、恢复码、刷新后状态、关闭认证和限流。

`node tests/admin-account-flows.cjs`、`node tests/identity-features.cjs`：原账号管理和权限回归。`npm run admin:build`：前端类型检查及生产构建。

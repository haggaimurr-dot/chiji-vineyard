# 商品与批次资料

商品详情新增「批次溯源码」及「礼盒定制」。后台批次资料中的溯源码对应 `traceability.code`，填写时必须关联批次号，最多 120 字；买家可复制代码联系客服核实。此码由商家录入，不自动生成二维码，也未接入外部溯源查询服务。示例代码保留 `DEMO-` 标记；旧商品未填写时提示尚未提供。

后台可新增、开启或关闭礼盒定制，并维护说明、定制项目、起订量及周期，保存为 `giftCustomization`。仅开启的服务显示在详情页；双拼礼盒提供示例配置，家庭装默认不显示。点击「提交定制需求」进入现有合作表单，读取商品信息并预填商品名称、商品 ID、参考规格及起订量。买家补全联系人、地区等必填信息并同意隐私政策后提交至现有合作线索，渠道默认为企业福利。定制报价、交期与采购方案由商家沟通确认，普通购物袋及结算仍按原规格购买。

新增验证：`node tests/product-detail-extras.cjs`，覆盖复制失败、定制服务关闭、表单预填、隐私同意、线索提交与加载重试。

目前按 mock 数据完善阳光玫瑰、巨峰、双拼礼盒三款商品。小程序和运营后台共用 `miniprogram/data/product-content.ts` 中的品种、净重口径、保存说明、果园、批次、采收与包装日期、包装说明及溯源流程。所有批次保留 `DEMO-` 前缀和 `traceability.demo: true`；日期、果园及流程均为示例，不作为真实发货凭证。预售礼盒未采收，采收及包装日期留空。

后台「商品与库存 → 编辑」可维护品种、图片说明、详情图库（每行一个地址）、净重口径、保存说明及批次资料，可添加或删除溯源流程。规格净重仍在每个 SKU 的重量说明中填写。小程序详情页展示所选规格和净重口径，选择规格后同步显示，并在示例批次商品顶部及产地溯源区域标注示例资料。

采收和包装日期必须为有效的 YYYY-MM-DD 日期，包装日期不得早于采收日期，填写包装日期时须已有采收日期。预售允许两个日期都留空。后台、mock 保存接口及 Go 保存接口执行相同规则；旧商品没有批次资料时继续兼容。

切换真实资料时，录入可核实的果园、批次、日期、包装和实拍图，并在资料类型中选择「真实资料」。此选择是商家对资料来源的声明，系统不会自动验证真实性。商品页记录当前批次；实际订单发货批次以包装标识及客服核实为准，尚未建立逐订单批次绑定。新增字段保存在现有商品 JSON payload，无需修改数据库表。

验证：`node tests/product-content.cjs`；`npm run check`；在 backend 目录执行 `go test ./...`。

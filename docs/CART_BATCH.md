# 购物袋批量操作接口

通过现有 `POST /api` 入口调用，使用小程序登录凭证，`action` 为 `cart.batch`。

```json
{
  "action": "cart.batch",
  "data": {
    "operation": "delete",
    "skuIds": ["sku-1", "sku-2"]
  }
}
```

- `delete`：删除指定规格。
- `favorite`：先收藏指定规格对应的商品，再删除这些购物袋项目。同一商品多个规格只收藏一次。
- `select`：批量设置勾选状态，额外传入布尔值 `selected`，支持全选与取消全选，不改变数量。

每次传入1–100个不重复的规格编号，每个编号最多80个字符。成功返回现有标准响应，其 `data` 为更新后的购物袋列表，与 `cart.get` 一致。

接口只操作当前登录用户的购物袋，商品编号从用户购物袋读取。不存在的项目跳过，重复请求安全；移入收藏遇到不存在或下架商品时整批失败。正式模式通过一个数据库事务保存收藏和购物袋变更，任何写入失败均回滚。勾选和删除不依赖当前库存或商品上架状态。事务提交后回读失败或网络中断时，客户端刷新列表并允许重试；请求失败不能据此判断事务是否已经提交。

小程序管理模式的批量删除、移入收藏及全选已接入该接口，保留删除确认和操作期间按钮锁定。演示模式支持相同参数与批量校验；设备本地存储不具备数据库事务能力，存储写入失败后可能已保存收藏但仍保留购物袋，重试不会产生重复收藏。无需新增数据库表。

专项验证：在 `backend/` 执行 `go test -run TestCartBatch -v`，根目录执行 `npm run test:cart`、`npm run mini:typecheck` 和 `npm run mini:build`。完整回归使用 `go test ./...` 和 `npm run test:flows`。

## 失效商品集中清理与凑单提示

- `cart.get` 和批量操作结果保留所有购物袋记录，包括商品下架或删除、规格停用或删除；这些记录的 `product` 或 `sku` 可为空。客户端将上述记录及库存为零、限购为零的商品集中展示在“失效商品”区域，显示原因和“一键清理”。确认后通过现有 `cart.batch` 的 `delete` 操作清理；取消、失败及重复点击均有保护。
- 失效商品不参与勾选、合计、全选、收藏及结算。购买数量超过最新库存或限购时，商品保留在可购买列表中，显示调整提示，并阻止直接结算。
- 凑单提示通过 `address.list` 获取默认地址（无默认地址时取第一个地址），再对当前勾选商品调用 `order.quote`，按实际免邮门槛展示差额和“去凑单”入口。没有地址时标明使用默认配送规则；达到门槛时显示已免基础运费，地区附加运费单独提示，不可配送时展示原因。
- 勾选或数量变化立即重算；过期响应不会覆盖最新选择。报价失败显示提示不可用，不影响结算。最终运费以结算页的地址及配送日期为准，无需新增数据库表。

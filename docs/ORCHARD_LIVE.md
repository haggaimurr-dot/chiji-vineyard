# 果园现状 · 双机位直播

首页的“查看果园现状”进入独立页面，切换“果园内部”和“园外摊位”。首页仍以采摘照片和简短介绍为主，公告、预约及日历继续折叠。

## 当前完成

- 小程序双机位切换、点击观看、默认静音、暂停、等待、断流提示与重新连接。离开页面停止播放，旧机位回调和过期配置请求不会覆盖当前状态。
- 后台“运营配置 → 首页与隐私政策”的“双机位直播”配置，两个机位分别设置开关、播放地址和直播时间说明。随首页配置保存、回读、历史记录和回滚。
- Go 后端持久化直播配置并验证地址；仅接受 HTTPS HLS `.m3u8` 播放地址，可带签名参数。开启机位必须有地址；旧配置不含直播字段仍正常读取。
- 未配置时显示“直播暂未开启”，没有示意直播、虚构在线人数或伪造现场画面。地址已配置也不会直接标记“直播中”，播放事件后才显示“正在播放”。

## 后续接入

当前两个机位尚未接入摄像头和直播服务。本次完成页面、配置和播放逻辑，未验证真实流播放。

摄像头 → 直播服务推流/转码 → 两个独立 HTTPS HLS 播放地址 → 后台保存启用 → 微信真机观看。摄像头的 RTSP 地址或设备登录密码不能直接填写到公开播放配置中。当前后端不做代理转码、不签发短期播放地址，也不检测机位是否实际在线。

播放器使用小程序 `video` 播放 HLS，现场画面有缓冲延迟；暂不集成 `live-player` 的低延迟协议。[腾讯云直播 SDK 文档](https://main.qcloudimg.com/raw/document/product/pdf/454_72594_cn.pdf) 说明 HLS 由 `video` 组件播放，而 `live-player` 不支持 HLS。接入前需按微信当前规则配置播放域名及流服务跨域/防盗链，iOS、Android 各用真机验收。签名地址过期后需在后台更新，本版本没有自动续签功能。

## 具体验收步骤

| 功能 | 操作步骤 | 预期结果 |
|---|---|---|
| 首页入口 | 打开首页，向下找到“查看果园现状”，点击 | 进入果园现状页面；首页业务模块仍默认收起 |
| 未接入 | 保持两个机位关闭，打开页面，分别点击“果园内部”和“园外摊位” | 两个视角均显示“直播暂未开启”，没有播放器或示意现场 |
| 配置独立保存 | 后台进入首页配置，为两个机位分别填写不同的 HTTPS `.m3u8` 地址和时间，启用后保存，刷新后台回读 | 两个机位配置保留；首页配置历史可见本次变更 |
| 无效地址 | 尝试开启空地址；或输入 HTTP、RTSP、MP4、含密码地址，再保存 | 前后端拒绝保存并给出提示 |
| 预览状态 | 预览首页，点击“查看果园现状” | 显示两个机位的启用/未接入状态和时间说明；明确这里是配置预览 |
| 真实播放（待地址） | 配置实际在线的 HLS 流，微信真机进入对应视角，点击“开始观看” | 显示该机位实际画面，默认静音，可用播放器控件暂停、开启声音、全屏 |
| 机位切换（待地址） | 果园内部播放时切到园外摊位，再开始观看 | 旧画面停止，切换后仅播放新机位；不会同时播放两个流 |
| 断流（待地址） | 播放过程中关闭推流或断开网络 | 等待时显示连接状态；连接等待超过20秒或播放器错误时显示连接失败，可重试 |
| 后台关闭 | 关闭某个机位并保存，小程序点击“刷新机位状态” | 该机位显示未开启；另一个机位不受影响 |
| 离开及重返 | 观看时返回首页，再重新进入；或切小程序到后台后恢复 | 离开时停止播放；重返重新读取配置，用户点击后再观看 |
| 配置回滚 | 后台回滚到前一个首页配置，小程序刷新状态 | 恢复该版本机位配置；回滚到无直播字段的历史配置时两个机位关闭 |

自动检查：`node tests/orchard-live.cjs`；Go `go test ./...` 含双机位校验和 JSON 持久化往返测试。真实摄像头画面、延迟、全屏及声音仍需提供地址后做真机验收。

2026-10-10本机验证结果：小程序和后台构建通过，直播状态/失效回调/超时测试通过，原首页功能回归通过，Go测试通过。真实本地后端已验证空地址启用被拒绝、两个关闭机位保存及回读一致；浏览器已验证双机位配置控件及首页机位预览，无页面脚本错误。[本机验证记录](test-evidence/2026-10-10-orchard-live/results.json)。后台使用真实本地数据库，小程序仍使用演示数据，尚未做两端实际直播联调。

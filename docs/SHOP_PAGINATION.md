# 商城分页与加载优化

商城使用新增的 `product.search` 接口，传入 `category`、`keyword`、`sort`、`offset` 和 `limit`，返回 `items`、`total`、`offset` 和 `limit`。默认每页20款，后端单页最多50款。原 `product.list` 保持兼容首页与已有调用；商城不再使用它的100款上限。

搜索、分类与排序在数据库分页前完成，仅展示已发布商品。多关键词同时匹配商品名称、简介、产地、标签或在售规格，`%`、`_` 按普通字符处理。价格取在售规格最低价，无在售规格的商品排在价格排序末尾；销量取在售规格净销量总和。排序相同时按运营排序及商品ID确定顺序。

每个非空页使用4次查询：总数、商品页、批量规格、当前用户在该页的关注状态。使用只读可重复读事务，保证单次请求的总数、商品及规格来自同一快照；列表不传详情长文本、相册和溯源信息，详情仍由详情接口获取。不需要数据库结构变更。

小程序提供300毫秒搜索防抖、键盘确认立即搜索、图片懒加载、触底及按钮加载更多。重复触底只发出一次请求。追加失败保留商品及偏移量，点击重试原页；切换筛选、刷新或离开页面使旧请求失效。追加仅通过 `setData` 传输新卡片，收藏操作仅更新对应字段，保留已有图片失败状态。

分页使用偏移量，跨页期间若商品上下架、运营排序或价格销量变化，顺序可能改变。客户端按ID去重，下拉刷新可重新获取最新列表；跨页浏览不提供固定快照。

## 本地验证

- `npm run test:shop`：137款商品、末页、完整追加、重复触底、失败后原偏移重试、局部更新、搜索防抖、旧响应丢弃、分类切换、页面生命周期、演示分页及原商品搜索排序流程。
- 后端 `go test ./...`：第120条之后分页、全部排序、字面关键词、参数上限、单页4次批量查询、用户关注隔离、空页和失败回滚，以及已有后端回归测试。
- `npm run mini:build`：生成小程序相邻JavaScript文件。
- `npm run check`：小程序及后台类型检查、后台构建。

上述接口测试使用数据库驱动替身，未执行真实MySQL压测或微信真机验收。部署时同步发布后端和小程序；真机验证搜索、触底、断网重试及图片懒加载，真实数据库验证超过100款商品时的搜索和各排序结果。

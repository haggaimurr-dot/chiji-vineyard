# 用户券包与自动匹配最优券

购物袋和「我的」新增「我的券包」入口。输入运营后台配置的兑换码，即可将券加入当前用户券包；大小写和首尾空格会统一处理，每人每码只保存一张。重复兑换不会新增次数，已使用的券不会恢复。券包支持可使用、其他状态、全部筛选，展示门槛、抵扣额、北京时间有效期和状态。未达到本单门槛的券在结算选券时不可选择。

结算默认自动匹配券包中适用于本单的券，也可以选择指定券、兑换并使用或明确不使用券。每次地址、配送日期变化或重新进入页面都会重新报价，手动选择模式保持不变；自动模式重新匹配。没有适用券时按无券报价，加载失败提供重试并禁止支付。兑换只加入券包，不保证当前订单达到使用门槛。

匹配按实际抵扣金额从高到低排列；券抵扣不超过商品金额减1分，不抵运费。实际抵扣相同时，优先到期日期更早的券，再按编码升序决定。包邮判断继续按优惠前商品金额计算，不叠加多张券。待付款订单占用券；未支付订单取消或关闭后释放；支付后及退款后均不返券。

## 正式接口与数据

- `coupon.wallet`：无参数，仅返回登录用户已兑换的券；每次查询依据当前优惠券配置和订单状态计算状态。配置删除后保留兑换时名称和金额快照，以失效状态展示。
- `coupon.redeem`：`{code}`，登录用户幂等兑换。拒绝不存在、已停用或已过期的券，允许提前兑换尚未生效的有效配置。
- `order.quote`：新增可选 `autoCoupon: true`，开启时忽略请求中的手动编码，从用户券包选择最优券，结果在 `couponCode` 返回具体编码。
- `order.create`：提交报价返回的具体 `couponCode`；在事务内重新验证规则、门槛和占用，配置变化或并发占用会拒绝下单。幂等重试沿用原订单与具体编码，不重新选券。占用查询使用锁定读取，避免 MySQL REPEATABLE READ 的旧快照放行重复用券。

原有直接兑换码报价和下单接口兼容；旧订单不会自动补成券包记录，用户可以将旧兑换码加入券包后查看其已使用/占用状态。券包读取当前运营配置，修改规则会影响未使用券；这沿用原有兑换码规则。没有公开列出后台全部兑换码的领券接口。

## 上线与验证

已有数据库先执行 `backend/migrations/20261008_coupon_wallet.sql` 创建 `user_coupons`，再协调发布后端和小程序；新数据库使用更新后的 `backend/schema.sql`。运营后台沿用现有优惠券配置，无需新增后台页面。

演示模式券包存储于当前设备 `chiji_demo_coupon_wallet`，与正式用户数据隔离，初始为空。示例码 `DEMO10` 为满99减10，`DEMO20` 为满199减20；示例规则与后台演示配置独立，不发放真实权益。

运行 `npm run test:coupons` 验证兑换、持久化、占用/释放、支付后状态、最佳抵扣、手动与自动选择、旧响应保护和服务端用户隔离/快照失效。后端专项脚本在临时包中直接加载生产券包源码及相关生产函数，使用 SQL 驱动模拟；不等于真实 MySQL 并发验收。回归命令为 `npm run test:cart`、`npm run test:checkout`、`npm run mini:typecheck` 和 `npm run mini:build`。

本次后端 `go test ./...` 被仓库其他模块缺失定义阻塞，包括 `TicketReturn`、`ReturnAction`、`courseList`、`reconcileFinance`、`videoProgress` 等。新增券包专项编译与测试通过，但整个服务编译和真实数据库联调仍待这些依赖补齐后验证。

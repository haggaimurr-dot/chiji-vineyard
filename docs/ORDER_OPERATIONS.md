# 批量发货、订单导出与快递100电子面单

## 拣货单与异常订单工作台

后台「订单与售后」新增三个入口：订单与售后、拣货单、异常订单工作台。

拣货单默认查询待发货订单，支持搜索与分页。勾选当前页1至50笔订单后点击「生成拣货单」，服务端在同一只读快照内重新核对订单是否已确认、已付款、待发货且无进行中售后。部分退款沿用现有可发货规则。不可拣货、缺失或重复的订单会使整张单生成失败。生成结果按商品名称与规格汇总数量，并保留逐单收件资料、配送日期、备注与商品明细，可打印A4或导出CSV。生成和打印不会改变订单状态；拣货单是生成时的快照，出库前需核对最新订单状态。

异常订单工作台查询全部匹配订单并分页，支持关键词搜索、按类型筛选和订单导出。范围包括微信发货同步FAILED、发货提醒FAILED/UNCERTAIN、退款FAILED、已开票邮件FAILED/UNCERTAIN；每单显示全部匹配异常原因。可复用订单列表的同步重试、提醒重试、发票邮件操作及下方售后处理。结果待核实应先核对服务记录，避免重复发送或退款。异常随业务状态更新自动移出工作台，没有单独的“忽略异常”状态。

新增 `admin.order.picking` 接口，参数 `{orderIds:[...]}`，返回重新校验后的订单数组，要求 `order.read`；CSV导出按钮沿用 `order.export` 权限。`admin.order.search` 及订单导出新增筛选值 `exceptions`、`sync_failed`、`notice_exception`、`refund_failed`、`invoice_exception`。无需数据库迁移。

## 操作流程

后台「订单与售后」支持勾选订单、导出选中订单或全部筛选结果，以及批量登记发货。批量发货每次最多50单，每单填写承运商名称、编码、运单号；相同承运商的同一单号不能用于不同订单。提交后逐单显示结果，成功订单保留，不因另一单失败回滚；再次提交相同已发货信息不会重新通知客户。微信发货同步失败单独显示，可使用现有重试入口。

CSV 导出包含订单状态、商品快照、金额、收件资料、配送日期、备注、发票及物流信息。筛选导出在数据库按搜索与状态筛选后处理，包含分页外的数据；单次上限10000单，超过上限需缩小范围。文件使用 UTF-8 BOM，适合 Excel。手机号、单号等文本保留，可能执行公式的字段作转义。只有已登录且有效的管理员可导出，审计记录只记模式及数量。

电子面单使用已配置的快递网点/月结账号，通过快递100生成真实运单号及图片。填写实际包裹重量（公斤），选择已开通的承运商，创建后打印实际图片。创建面单保留原有备货状态；实物交给快递后，仍需登记或批量登记发货。已生成面单的订单，发货时承运商编码与运单号必须与面单一致。

同一订单重复创建或打印已就绪面单均复用原运单号与已保存图片，打印不会再次向快递100取号。演示后台明确显示演示状态，不申请真实运单号；正式服务缺少凭据时提示未开通。

打印前选择与快递100 V2 模板相同的纸张尺寸，支持100×100、100×150、100×180、100×200毫米。在打印机驱动中设置相同纸张，关闭浏览器页眉页脚并按原始尺寸输出；首次使用应核对条码清晰度与打印边界。

## 服务端配置

后台「运营配置 → 电子面单 · 账号与协议价」支持编辑寄件人、手机号、完整地址，分别启停顺丰、圆通、中通、申通、韵达、EMS、京东和极兔，填写各自网点/月结账号、密码/顾客编码、校验码、网点、产品、付款方式及 V2 图片模板。仅超级管理员能读取或保存配置。账号、密码及校验码保存后不回显，留空保留原值；配置版本冲突会拒绝保存，需要重新读取。服务端企业 KEY/SECRET 仍通过环境变量提供。

首次读取沿用下文的环境变量配置；首次后台保存后，账号和寄件资料以数据库 `configs` 表的私有 `waybill` 配置为准，之后改环境变量不会覆盖已保存的配置。无需新增表；已有真实面单仍沿用 `order_waybills` 表。该私有配置不进入公共配置接口或配置版本历史，审计只记录版本与数量，不包含账号、寄件资料或密码。

演示模式提供 8 家承运商的示例账号及顺丰、圆通、中通示例协议价。后台保存的演示寄件资料、启停状态及协议价在当前标签页会话内保留，刷新仍可读取；输入的凭据只转成“已保存”标记，不保存在浏览器中。所有演示号码及打印内容均标注不可交寄。2026-10-06 本次按用户要求使用 mock 数据验收，不发起真实取号或物理打印。

## 运费比较

在上述配置中录入签约网点提供的协议价：目的省份（空表示全国）、首重及首重价、续重单位及单价、固定附加费、预计时效。金额单位为分，重量单位为公斤，协议价重量精确到克。同一承运商、同一目的省份只能有一条配置；指定省份的完整价目表优先于全国价。

订单中打开「电子面单」，填写实际包裹毛重（0.01至100公斤），点击「比较运费」。服务端使用订单保存的目的省份计算 `首重价 + ceil(max(重量 − 首重, 0) / 续重单位) × 续重价 + 附加费`，按预估金额升序显示，并可选择承运商后取号。修改重量会清除旧报价。关闭或账号未配置完整的承运商不参与比较；没有适用协议价的承运商显示“暂无报价”，不视作免费运输。

比较结果为已录入协议价的预估，未对接承运商实时计价；体积重、偏远区县、冷链及未配置的特殊附加费可能影响最终费用，以承运商账单为准。后台的订单配送收费规则与此模块的商家寄件成本分别配置。

## 企业账号与环境变量

先在快递100企业账号开通电子面单服务及额度，向快递网点取得账号、密码、网点参数及产品权限，并配置对应的 V2 图片模板。现有轨迹查询的 CUSTOMER 不等于电子面单 SECRET。

在云托管配置 `.env.example`：沿用 `KUAIDI100_KEY`，新增 `KUAIDI100_SECRET`、`KUAIDI100_SENDER_NAME`、`KUAIDI100_SENDER_PHONE`、`KUAIDI100_SENDER_ADDRESS` 及 `KUAIDI100_WAYBILL_ACCOUNTS`。旧数据库执行 `backend/schema.sql` 新增的 `order_waybills` 和 `shipment_numbers` 建表语句，再部署后端与后台。

账号配置是以承运商编码为键的 JSON，只填已经签约的网点/月结账号。例如：

```json
{
  "SF": {
    "partnerId": "网点提供的月结账号",
    "partnerKey": "网点提供的顾客编码",
    "partnerSecret": "网点提供的校验码",
    "tempId": "顺丰V2图片模板ID",
    "expType": "顺丰标快",
    "payType": "MONTHLY"
  },
  "ZTO": {
    "partnerId": "电子面单账号",
    "partnerKey": "打单密钥",
    "net": "网点编码",
    "tempId": "中通V2图片模板ID",
    "expType": "标准快递",
    "payType": "SHIPPER"
  }
}
```

支持 SF、YTO、ZTO、STO、YD、EMS、JD、JT，对应 shunfeng、yuantong、zhongtong、shentong、yunda、ems、jd、jtexpress。所有账号需要 `partnerId`、`tempId`、`expType`；除京东外需要 `partnerKey`，顺丰还需 `partnerSecret`，中通/申通还需 `net`。支持选填 `partnerName`、`checkMan`、`code`。未填 `code` 时，顺丰/中通/申通分别使用 sf_secret、ztoOpen、44。产品、账号类型及付款方式以网点实际权限为准；允许寄方付 SHIPPER 或月结 MONTHLY，省略为寄方付。

当前实现为原生网点账号、单包裹、V2 IMAGE 模式，使用本地打印设备。电商平台授权账号（菜鸟、淘宝、拼多多等）有不同授权及 PDF 返回流程，本配置不启用；快递100云打印机模式亦未启用。前端只看到已配置完整的承运商名称和编码，密钥、商家账号及寄件资料保留在服务端。

## 状态与异常

| 状态 | 含义与处理 |
| --- | --- |
| CREATING | 已保存占位，正在申请；重复操作只读取已有状态，超过两分钟的中断请求转为待核实。 |
| READY | 已取得真实单号并保存实际图片，可重复打印。 |
| FAILED | 服务商明确拒绝下单，如账号、余额、模板错误；修正后可由运营再次点击创建。 |
| UNCERTAIN | 网络结果未知、中断，或已生成单号但图片尚未保存；不会自动重新下单。 |

已有单号且图片异步生成时，「刷新面单」仅下载原图片并保存，不重新取号。图片未生成、异常内容、非快递100链接、超过4MB 均保留待核实，不用本地排版替代真实面单。

若下单超时且没有可靠单号/图片链接，到快递100后台按订单号核实并联系服务商确认原面单是否已生成或已取消。应用没有清除未知结果、自动重新下单的接口，数据库记录不得未经核实删除或重置。未确认面单的订单不能绕过流程手填另一个单号发货。

READY 图片保存在私有 `order_waybills.content`，不依赖短链有效期。管理员经 API 取得 PNG/JPEG/WebP 图片；小程序订单、公开素材、导出文件均不包含面单图片、供应商链接或密钥。重复打印读取原图片；图片响应使用私有、禁止缓存设置。数据库备份和保留期限按商家隐私政策管理。

## 接口

以下 action 使用 `POST /api`，要求管理员身份。

| action | data | 返回 |
| --- | --- | --- |
| admin.order.batchShip | `{items:[{orderId,carrier,carrierCode,trackingNo}]}` | `{results,succeeded,failed}`，逐单结果 |
| admin.order.export | `{keyword,filter}` 或 `{orderIds:[...]}` | `{filename,content,count}` |
| admin.waybill.config | `{}` | `{configured,carriers,message?}` |
| admin.waybill.settings | `{}` | 超级管理员：寄件资料、脱敏账号、协议价、revision |
| admin.waybill.settings.save | `{revision,senderName,senderPhone,senderAddress,accounts,rates}` | 超级管理员：保存并返回脱敏配置，账号敏感字段留空保留 |
| admin.waybill.quote | `{orderId,weight}` | 查看订单权限：目的省份、重量、版本、排序后的预估运费和缺失报价 |
| admin.waybill.get | `{orderId}` | 面单元数据或 null |
| admin.waybill.create | `{orderId,carrierCode,weight}` | 面单元数据 |
| admin.waybill.sync | `{orderId}` | 元数据；仅重取原图片 |
| admin.waybill.label | `{orderId}` | `{dataUrl,mime}`，已保存图片 |

面单元数据包含 `id`、`orderId`、`orderNo`、`carrier`、`carrierCode`、`trackingNo`、`labelUrl`、`status`、`error?`、`createdAt`、`updatedAt`。`labelUrl` 为需要管理员请求头的 `/admin/waybills/{id}/label`，不能作为公开素材链接。

## 验收

- 多单发货混合成功/失败，失败单保留备货状态；相同批次重复提交无重复通知；同运单用于不同订单拒绝；微信同步失败可见且不丢失发货。
- 选中导出只含所选数据；筛选导出覆盖分页外订单；中文、逗号、换行、手机号、长单号、公式字符正确；未登录及普通用户不得导出。
- 缺密钥、网点账号、寄件人或模板时提示未开通，无虚构号码。
- 实际网点账号创建一单，核对号码、收/寄件人、重量、产品及纸张尺寸；再次创建/打印仍为同一号码，订单仍为备货中。
- 并发创建同单只下单一次；明确失败可修正后人工重试；超时/中断保留待核实，刷新及重复点击不得再次取号。
- 已取得单号但图片延迟时只重取原图片；保存后关闭供应商链接也能重复打印；无效 HTML、跨站链接、超大图片不得打印。
- 手填、批量及物流更正不能使用与 READY 面单不同的单号；未付款、已发货、退款中不能申请新面单；普通用户不能读图片。

本地 HTTP mock 和事务状态测试不能证明商家账号、额度、网点、打印机及实单出库已验收；部署前完成上述实单验证。

新增专项检查：`npm run test:waybills`；浏览器检查：启动 `VITE_USE_MOCK=true` 的后台，设置 `ADMIN_UI_URL` 后执行 `node tests/waybill-ui.cjs`。浏览器覆盖寄件资料保存/刷新、凭据不回显且不进入会话存储、按费用排序及承运商选择、重量变化清空旧报价、两次调用打印复用同一示例号码。Go 的 `go test ./...` 覆盖配置保存事务、版本冲突、敏感字段保留与脱敏、生产取号读取数据库寄件资料、省份价优先及续重边界；HTTP mock 返回的真实图片格式仍需最终通过物理打印验收。

接口依据：[快递100电子面单 V2](https://api.kuaidi100.com/document/dianzimiandanV2)、[承运商参数字典](https://api.kuaidi100.com/document/5f0ff6e82977d50a94e10237)。使用 `method=order`、`printType=IMAGE`，签名为大写 MD5(param+t+key+secret)。订单号作为 `orderId` 并设置 `reorder=false`；服务商仅在48小时内复用首次成功结果，本地持久化记录继续防止之后重复下单。

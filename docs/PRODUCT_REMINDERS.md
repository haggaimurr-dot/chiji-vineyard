# 自定义目标价格与提醒历史

在商品详情选择规格，填写可选的「目标价格（元）」后开启降价提醒。留空保留原有规则：同一规格的现价低于关注时实售价。填写目标价后，现价小于或等于目标价且有货、可购买时满足微信发送条件。金额最多两位小数，初次设置不能高于当前规格价。

已开启的提醒可在商品详情或「我的 → 降价提醒」修改目标价，也可恢复「降价即提醒」。修改后的目标价不能高于原关注价。修改条件保留关注规格、关注价及微信授权状态；已发送的授权不会因修改而再次发送。发送中或结果不确定时禁止修改，避免并发条件改变。再次接收微信提醒需取消后重新设置，并重新主动订阅。

「我的 → 提醒历史」以及收藏、到货、降价列表中的历史入口按时间倒序分页展示到货/降价微信发送记录，包括商品名称、规格、触发时价格、目标价、北京时间、结果及失败说明。已发送、失败、授权失效和结果待核实分别显示。记录保留发送时快照，取消关注或商品下架不删除历史。历史从升级后开始保存，不补造过去的发送记录。

发送前，原子提交发送占用与历史快照；微信请求完成后，原子保存结果与历史状态。请求结果不明确或进程中断时保留待核实记录，不自动重复发送。明确失败后的重试另存一条历史。

演示模式仅在读取商品/提醒历史时检测条件，并在当前设备保存小程序内提醒记录，明确标为演示，不发送微信消息。同一轮关注只记录一次；取消再开启可以生成新记录。演示与正式数据独立。

## 通知任务看板与失败处置

后台「收藏与提醒」集中展示到货和降价通知任务，支持状态统计、类型/状态筛选、分页及用户发送历史。「失败处置入口」筛选失败、授权失效、待核实与发送中任务。发送中任务仅供查看，禁止人工改动。

查看沿用 `product.read` 权限，处置沿用 `product.write`。明确失败可重新排队或停止；授权失效只能停止，重新授权须用户主动订阅；待核实可在确认微信发送成功后标记已发送，或停止，不能直接重发。操作必须填写核查备注，后端锁定最新任务、拒绝过期状态，并将状态修改与操作日志在同一事务提交。用户取消关注后不能重新排队。处置不删除收藏、关注及失败历史。

重新排队仍由现有内部定时发送入口执行，发送前继续检查授权模板、商品可购条件及降价目标。明确失败原有自动重试规则保持不变。待核实人工处理同步标注相关未决历史。演示模式仅模拟处置，页面刷新恢复示例任务。

接口：`admin.reminder.tasks`、`admin.reminder.history`、`admin.reminder.resolve`。沿用现有表结构，无新增迁移。功能测试：`node tests/reminder-tasks.cjs`，后端 `TestReminderResolutionGuards` 与 `TestReminderResolveTransactions`。

## 数据库升级步骤

已有数据库上线前执行一次 `backend/migrations/20261007_reminder_targets_history.sql`，增加 `price_drop_notifications.target_price` 与 `product_reminder_history`。原记录默认目标价为 0，保留原有降价条件。新库直接使用 `backend/schema.sql`。

继续使用原到货/降价模板配置及内部定时发送入口。后端使用微信身份查询本人历史，不接受客户端提供的用户身份。

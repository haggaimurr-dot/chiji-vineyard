# 身份与权限

## 登录限流

后台登录每个账号在15分钟窗口内最多尝试5次，每个来源地址最多尝试30次。账号名去除首尾空格并忽略大小写；查到账号后还按账号ID计数，避免数据库排序规则中的别名绕过限制。初始化接口共用后台来源限额。小程序微信登录每个来源每分钟最多尝试30次。

成功和失败都计数，成功登录不会清空窗口。超过限额返回 HTTP 429，错误码 `LOGIN_RATE_LIMITED`、`Retry-After` 响应头与 JSON `retryAfter` 表示剩余秒数。后台登录按钮显示倒计时；窗口到期后自动允许重试。数据库安全检查失败时拒绝登录，不降级为无限制登录。

计数保存在 MySQL `login_limits`，多实例共享、服务重启不清空。计数键只保存来源/账号的 SHA-256 摘要，过期行在后续允许的登录请求中分批清理。

默认使用直接连接的来源地址，忽略客户端提供的转发头。经反向代理部署时，设置 `LOGIN_TRUSTED_PROXY_CIDRS` 为真实代理的 CIDR 列表（逗号分隔）；只有可信代理的 `X-Forwarded-For` 才会使用，并从右向左找到第一个非可信来源。代理应追加或重写此头；不要填写整个互联网地址范围。未配置时，代理后所有用户可能共享同一个来源限额。

## 细粒度权限

超级管理员在“运营配置 → 后台账号”添加账号时选择权限，或点击运营账号的“设置权限”修改。权限区分业务查看与操作：经营概览、商品查看/编辑、库存调整、订单查看/发货/导出、退款查看/审批、发票下载/开具与邮件、评价查看/回复及审核、内容查看/编辑与恢复/独立审核、线索查看/跟进、素材上传、配置查看。

商品保存包含SKU库存写入，因此需要同时拥有 `product.write` 与 `inventory.write`。业务写入通常需要配合对应查看权限才能使用后台页面。配置修改、配置历史与回滚、操作日志、账号管理仍限超级管理员。

旧运营账号尚无权限记录时保留原有业务权限；新账号界面提交显式权限列表。空列表表示可以登录，但没有业务操作权限。未知角色或未登记的管理接口无法访问业务。超级管理员始终拥有全部已登记权限。

权限保存在 `configs` 的 `auth.permissions.<账号ID>`，不需要修改管理员表。`admin.account.permissions` 接收 `{ accountId, permissions: string[] }`，与审计记录 `ADMIN_PERMISSIONS_SAVE` 在同一事务保存；失败整体回滚。创建账号时也支持 `account.permissions`，与账号创建及审计在同一事务保存。

每次后台请求从数据库检查当前角色和权限，旧Token不能保留已撤销的权限。JSON API、视频上传、私有面单下载都执行检查；拒绝返回 HTTP 403 与 `PERMISSION_DENIED`。`admin.session` 返回当前账号和权限，不返回密码资料。后台启动、每分钟与权限拒绝后刷新会话；菜单与操作按钮按权限显示或禁用，接口仍以服务端校验为准。

演示模式在本浏览器会话中模拟账号权限、撤权、账号限流与倒计时；其权限与计数不跨浏览器共享，不能替代服务端安全检查。

## 会话列表、单设备撤销与自助注销

这里的自助注销指退出登录。接口使用现有 `POST /api` 的 `{ action, data }` 格式和 Authorization 令牌。

| 功能 | 后台 action | 小程序 action | data |
| --- | --- | --- | --- |
| 本人有效会话列表 | `admin.session.list` | `auth.session.list` | `{ "limit": 20, "offset": 0 }` |
| 撤销本人指定登录会话 | `admin.session.revoke` | `auth.session.revoke` | `{ "sessionId": "列表中的id" }` |
| 退出当前登录 | `admin.logout` | `auth.logout` | `{}` |

列表返回 `{ items, hasMore }`，默认每页20条，最多100条，offset范围0–1000000。每项包含 `id`、`userAgent`、`ipAddress`、`createdAt`、`expiresAt`、`current`；时间为Unix秒。按登录时间及ID倒序，只展示本人、同一客户端类型的有效会话。后台密码或MFA变更后失效的旧会话不会展示。设备信息来自请求User-Agent，仅用于辨认；每次登录对应独立会话，同一设备多次登录也会有多条记录。

撤销和退出返回 `{ sessionRevoked: boolean }`，表示当前会话是否应清除。客户端收到true后清除本地令牌并回到登录页。退出接口忽略传入的其他会话或账号ID。后台退出按钮已接入服务端撤销；网络失败时保留登录状态并提示重试。撤销其他设备后当前设备继续登录。目标不存在、已撤销或不属于本人时采用相同成功响应，不披露他人的会话归属；跨账号或跨客户端类型不会修改目标记录。已经退出的令牌再次请求会返回401。

后台所有已登录账号均可管理自己的会话，无需业务权限。后台会话撤销与审计同一事务提交，审计失败回滚。小程序会话同样存于数据库，撤销支持多实例共享。所有认证请求校验服务端会话状态；后台私有面单和素材上传也沿用会话校验。数据库检查失败拒绝访问。撤销不会中断已经通过校验的在途请求，从下一次认证检查生效。

发布前执行 `backend/migrations/20261008_auth_sessions.sql`；新库执行完整 `backend/schema.sql`。本次升级使没有sid的旧令牌失效，用户需要重新登录。表中不保存完整令牌、密码或微信登录code。历史过期记录可由运维定期分批清理：`DELETE FROM auth_sessions WHERE expires_at<=UNIX_TIMESTAMP() LIMIT 1000`，无需保留到令牌过期之后。

## 部署与验证

已有数据库先执行 `backend/migrations/20261005_identity.sql`，再部署后端与后台。新数据库执行完整 `backend/schema.sql`。迁移只新增限流表，不改动既有业务数据。按部署拓扑设置可信代理范围。

本地验证：

```powershell
cd backend
go test ./...
cd ..
npm run test:identity
node tests/admin-account-flows.cjs
npm run admin:build
```

测试覆盖账号与来源限流、窗口恢复、数据库失败拒绝登录、转发头可信边界、数据库别名限流、旧会话撤权、导出/退款/素材权限拒绝、私有面单与视频上传拒绝、商品库存权限依赖、空权限与审计失败回滚。Go测试使用数据库测试驱动；上线前需在真实MySQL及代理环境复验并发限流与迁移执行。

# 定时发布、内容版本与阅读统计

在后台「种植内容」新建或编辑课堂内容，可保存草稿、立即发布或选择定时发布。所有定时输入和统计日期采用北京时间，与运营人员电脑的时区无关。

## 定时发布

选择「定时发布」并填写未来时间后保存，内容进入待发布状态。到期后服务端将内容转为已发布，记录实际内容版本；小程序首页推荐、课堂列表与文章详情使用同一发布状态。到期前不能通过文章详情接口访问待发布内容。

运行中的 Go 服务每30秒检查到期任务，文章读取也会补处理到期任务。服务停止或云托管缩容到零期间不会执行后台循环，下一次内容请求或服务启动后会补发；需要严格按时执行时，保持至少一个服务实例运行。多实例使用事务和行锁避免重复发布。同一内容改为草稿或直接发布会取消原定时任务。

## 内容版本

每次成功保存生成新的版本，定时发布也生成一个版本。历史记录保存当时的内容、发布状态、时间和操作者，可在「内容版本」查看。

恢复历史版本会生成新的草稿版本，并清除历史定时时间。检查内容后可再次发布。恢复不会删除后续历史记录，也不会重置阅读统计。旧文章按 V1 兼容，第一次修改或恢复时补存原始快照；不能找回此功能上线前未保存的历史修改。

保存和恢复都携带当前版本号；如果其他运营人员已经保存或定时任务已经发布，服务端会拒绝旧版本提交。保留当前编辑内容，重新读取最新版本并核对后再提交。

## 阅读统计

阅读次数为小程序成功打开并展示文章详情的次数。每次进入详情生成一个独立事件，同一次上报的网络或登录重试只计一次；课堂列表、首页推荐和后台预览不计入阅读。统计失败不会阻断文章阅读。

累计读者人数按微信用户去重，今日读者人数按北京时间当天去重。近14天趋势按北京时间零点划分，并补齐无阅读日期。每日读者人数相加不等于累计去重人数。服务端保存用户身份摘要和事件编号，后台只返回汇总数据。

后台演示统计明确标为示例，新建演示内容从零开始；演示小程序的统计保存在设备本地，仅有一个演示读者。两端演示数据独立，真实跨端统计需连接同一个后端。

## 数据库与接口

已有数据库先执行 [schema.sql](../backend/schema.sql) 中 `article_versions`、`article_schedules`、`article_reads` 的建表语句，再部署新版 Go 服务。三张表独立保存历史快照、待发布任务和阅读事件，无需修改原 `articles` 表结构。

| 接口 | 参数 | 用途 |
| --- | --- | --- |
| `admin.article.save` | `article`，已有内容含 `version` | 保存新版本，定时内容附 `scheduledAt` |
| `admin.article.versions` | `articleId` | 查询历史快照 |
| `admin.article.restore` | `articleId`、`version`、`expectedVersion` | 将指定版本恢复为新草稿 |
| `admin.article.stats` | `articleId` | 累计、今日和近14天统计 |
| `article.read` | `articleId`、`eventId` | 按登录用户幂等记录阅读 |

`scheduledAt` 使用带时区的 RFC3339 时间，后台将北京时间转换为 UTC 后发送；`eventId` 为1–128位字母、数字、下划线或连字符。管理接口需要有效管理员身份，阅读接口从登录令牌取得读者身份。

## 验证

本地运行 `npm run test:content`、`npm run check`、`npm run mini:build`，并在 `backend/` 执行 `go test ./...` 与 `go vet ./...`。

部署环境需用真实 MySQL 验证以下流程：

- 创建一分钟后的定时文章，到期前首页、课堂和详情不可见，到期后可见；刷新不会产生重复发布版本。
- 使用非北京时间的浏览器选择发布时间，核对后台显示及服务端 UTC 时间；跨北京时间午夜核对今日统计。
- 两个编辑窗口打开同一版本，先后保存，后提交者收到冲突提示；定时任务与编辑同时执行时也不能覆盖新版本。
- 查看、恢复旧版本，确认正文、视频和图片保持当时内容，恢复结果为新草稿且统计不变。
- 同一读者进入两次、两个读者各进入一次，分别核对阅读次数和去重人数；重复相同事件只记一次，未发布内容拒绝上报。
- 检查列表加载、空结果、异常重试、无历史或无阅读数据、抽屉滚动和较小桌面窗口；阅读上报失败仍可正常阅读。

新增内容审核、标签库和素材库的流程及权限说明，见 [内容管理](CONTENT_MANAGEMENT.md)。

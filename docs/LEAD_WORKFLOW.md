# 合作线索负责人、历史与提醒

在后台「合作线索」点击「跟进 / 历史」，可同时更新状态、分配负责人、追加本次沟通备注和设置下次跟进时间。负责人来自已启用的管理员账号，运营人员也可分配；选择「尚未分配」可取消分配。支持按负责人、未分配线索和提醒状态筛选，与原有关键词、状态、渠道和地区筛选组合使用。

每次实际变更都会生成历史记录，显示操作人、时间、变更类型和当时的状态、负责人及提醒。新增备注不会覆盖历史；相同的非空备注再次提交也视为一次新的跟进。旧备注保留，无法确定的旧记录时间标为未知。备注最多2000字。CSV 导出全部筛选结果，包含负责人、提醒时间及完整跟进记录。

## 跟进提醒

提醒时间输入按浏览器本地时区解释，提交时转换为 UTC；列表及历史时间按北京时间展示。新增或重新开启待处理提醒必须使用未来时间。提醒可标记完成、重新安排或移除；线索成交或关闭后，现有待处理提醒自动完成。

后台顶部「跟进提醒」显示到期数量，打开后按时间列出待处理提醒；可切换全部或我的提醒，点击任一项进入对应线索。面板每分钟刷新，线索保存后立即刷新，回到页面时也会刷新。当前为后台站内提醒，关闭后台时不发送短信、邮件或微信推送。

## 保存与并发

保存会比较线索版本，避免覆盖其他运营人员刚提交的修改。发生冲突时，表单刷新最新状态并保留本次已编辑内容；核对提示及最新历史后再次保存。未编辑的字段合并最新值。如果最新记录加载失败，先点击重试刷新。

正式模式将线索、不可变历史及操作日志写入同一事务；任一写入失败均回滚。演示模式把线索和历史一起保存在本浏览器的 `chiji_admin_demo_leads_v1` 中，刷新后保留，沿用已有演示存储并补齐旧字段。数据损坏或存储空间不足时显示错误并保留原数据，不自动覆盖。

## 部署与验证

已有数据库先执行 [schema.sql](../backend/schema.sql) 中的 `partner_lead_history` 建表语句，再部署后端和后台。负责人、提醒和版本保存在原线索 JSON 中，无需修改 `partner_leads` 字段；旧线索默认未分配、未设置提醒、版本为0。历史读取自动合并旧跟进记录并按 ID 去重。

本地检查：`npm run check`、`npm run test:leads`，在 `backend/` 运行 `go test ./...` 和 `go build ./...`。实际界面检查与截图见 [验收报告](LEAD_WORKFLOW_TEST_REPORT.md)。生产数据库和部署环境需另行验证。

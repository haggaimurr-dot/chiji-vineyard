# 内容审核、标签库与素材库

后台「种植内容」包含内容列表、内容审核、标签库和素材库四个页签。

## 内容审核

在内容列表将草稿「提交审核」，在内容审核页预览并选择「审核通过」或「退回修改」。退回原因必填，最多500字。审核通过后保持草稿，由运营人员回到编辑器选择立即发布或定时发布。

提交、审核、编辑和恢复都校验当前内容版本。两人同时处理时，旧版本请求被拒绝；提交与审核生成历史版本并写入操作日志。修改已经送审的标题、摘要、正文、封面、视频、品种、阶段或标签，会将审核状态改为待提交，须重新提交审核后才能发布。只调整发布状态或发布时间不会使已通过审核失效。恢复已参与审核的文章时，审核状态重置为待提交。

本次保留原有直接发布流程：未曾提交审核的内容仍可直接发布；文章一旦参与审核，后续发布须经过审核。审核使用独立 `article.review` 权限，阅读使用 `article.read` 权限。

## 标签库

支持新增、编辑、搜索、移出标签，并在内容编辑器多选关联。文章最多20个标签，每个最多80字，搜索文章时包含标签文本。

文章保存标签名称。标签改名后，新关联使用新名称，既有文章保留原名称；移出标签后既有文章仍保留，可在编辑器取消关联。这使历史内容与版本记录保持原始语义。

## 素材库

支持图片上传（JPG、PNG、WebP，最多4MB）及图片、视频 HTTPS 地址登记，记录名称和备注，可按类型或关键词筛选。编辑内容时可从素材库选择封面或视频；视频仍经过原有播放校验。视频文件上传沿用内容编辑器中的 MP4 上传功能。

移出素材库仅删除库记录，保留已上传文件及文章使用的素材地址，不影响已发布文章或历史版本。素材维护使用 `media.upload` 权限，标签维护使用 `article.write` 权限；服务端按资源类型再次校验权限。资源记录带版本号，防止旧编辑覆盖新的修改。

正式库记录使用现有 `configs` 表的 `content.resource.*` 键，文章审核信息和标签写入原有文章 JSON，无需新增数据库表。版本与审核功能依赖原有 `article_versions`、`article_schedules` 和 `article_reads` 表。演示模式将文章和库记录保存在当前浏览器本地，和正式服务数据独立。

## 验证

`npm run test:content` 覆盖库维护、校验、持久化、审核退回重提、过期版本拒绝、发布限制和恢复后的审核重置；在后台启动后运行 `ADMIN_UI_URL=<后台地址> npm run test:content-ui`，验证页签、上传、标签及素材关联、审核流程、刷新持久化和1024px布局。后端运行 `go test ./...` 与 `go vet ./...`；后台运行 `npm run admin:build`。

正式部署仍需连接真实 MySQL 和配置 `PUBLIC_BASE_URL`，验证上传地址可访问、多人同时审核和权限受限账号；本地测试使用事务模拟和浏览器演示模式。

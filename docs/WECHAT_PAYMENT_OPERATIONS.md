# 微信支付：自动对账与异常告警

后台「微信支付」仅超级管理员可见、可调用。新增功能需要执行 `backend/schema.sql` 中的 `payment_reconciliations` 和 `payment_alerts` 建表语句；已有订单表无需修改。上线后须使用真实商户配置验证账单下载和支付回调，本地演示模式不访问微信。

## 自动对账

后端启动时运行对账任务。每天北京时间 10:00 后的首次检查获取前一天 `SUCCESS` 交易账单，失败每 30 分钟重试。服务必须保持运行；云托管缩容到零时，请另配置定时请求 `POST /api`，请求头 `X-Job-Secret` 为 `INTERNAL_JOB_SECRET`，请求体为 `{"action":"internal.paymentReconcile","data":{}}`。指定 `data.billDate` 可补跑停机期间的账单。

管理员可选择近三个月内、今天之前的日期手动执行或重试。通过商户 API v3 签名申请账单、签名下载文件，并校验 SHA-1。下载地址限定微信支付官方 HTTPS 域名，禁止重定向，文件最大 32MB。MySQL 连接级锁阻止多个实例或管理员同时执行对账。

按商户订单号核对订单金额（整数分）、支付状态和微信交易号，同时检查本地已支付但账单缺失的记录。`NO_STATEMENT_EXIST` 视为空账单，仍检查本地已支付订单。其他下载、解析、数据库错误保存为 `FAILED`，不能显示为对账一致。

支付回调及查单入账保存微信 `success_time`，按真实支付时间划分北京时间账单日期。旧订单没有 `paidAt` 时，仍可从微信账单查出其金额、状态和交易号差异，但不能确定本地所属支付日，暂无法执行本地到微信的缺单检查。收款核对允许本地订单在付款后进入退款中或已退款状态，避免将正常退款误报为未入账；退款另以退款账单核对。

对账差异产生告警，不自动修改订单或触发退款。状态为 `RUNNING`、`MATCHED`、`DIFFERENCES` 或 `FAILED`，后台展示最近 31 个账单日期。重复执行更新同日结果；旧告警保留，核查后由管理员填写处理备注。

## 退款对账、结算与手续费统计

已有数据库上线前执行 `backend/migrations/20261008_payment_finance.sql`；新数据库使用完整 `schema.sql`。迁移新增 `payment_finance_runs` 及 `refunds.accepted_at`、日期索引。迁移只执行一次。

退款账单使用 `bill_type=REFUND`。以微信**受理退款日期**归属账单，核对商户退款单号、关联订单、申请退款金额（对应本地名义金额）、微信退款单号及成功状态；不能用应结退款金额代替申请退款金额，因为优惠券口径不同。账单为日切快照，`PROCESSING` 允许本地状态后续推进为成功或失败。微信账单有记录但本地不存在、本地未审批、金额/单号差异、微信成功但本地未完成，均产生 `REFUND_BILL_DIFFERENCE` 告警，不自动改资金或订单。

退款下单及查单验证成功后，以微信 `create_time` 保存首次受理时间；对这类记录执行本地到微信的缺单检查。旧退款或回调先到、下单结果丢失且未通过查单恢复受理时间的记录，仍可核对账单内记录，但不能确定受理日，不参加反向缺单检查。微信交易退款账单不含可用余额退款；商户使用此类退款时需另核对商户平台对应账单。

资金账单分别下载 `BASIC`（基本账户）、`FEES`（手续费账户）、`OPERATION`（运营账户），按记账日统计，不与退款受理日强行相等。每天北京时间10:00后自动执行，失败每30分钟重试，支持按日期和账单类型手动重试。接口 `admin.payment.financeReconcile` 入参 `billDate`、`kind`（`REFUND/BASIC/FEES/OPERATION`），仅超级管理员可调用，写入操作日志。同日期和账户重复运行覆盖结果，连接级锁阻止同类任务并发。

- 退款统计：申请退款金额、应结退款金额、成功退款笔数，以及账单手续费扣除、退还和净额。退还手续费按负值解析。
- 资金统计：收入、支出、净变动；手续费依资金业务类型 `扣除交易手续费`、`退还交易手续费`分别统计，净手续费 = 扣除 − 退还。
- 交易结算净额 = 业务类型为`交易`的收入 − 业务类型为`退款`的支出 − 净手续费。此值按当前账户统计，银行到账需另核对提现及银行流水。微信新增或调整业务类型可能需要更新分类；其他业务仍计入资金总收支。
- 三类账户分别展示，不与交易/退款账单手续费叠加，避免重复统计。页面支持账单类型、开始/结束日期筛选；概览返回最近124份账单，只汇总当前筛选内成功处理的数据，差异账单仍显示微信账单金额。未执行、处理中或失败的账单不计入总额，不能将缺失账期当作零收入。

账单下载复用签名、域名限制、拒绝重定向、32MB上限与SHA-1校验；先完整校验字段、重复单号、笔数及金额汇总再发布统计。下载、解析或数据库失败保存 `FAILED` 并产生 `FINANCE_RECONCILIATION_FAILED`。`NO_STATEMENT_EXIST`按空账单处理，退款仍执行可确定受理日期的反向检查。资金账单成功显示“统计完成”，表示微信账户统计完成，不表示与银行流水对账一致。

云托管缩容到零时可定时调用 `internal.paymentFinanceReconcile`，请求头同收款任务，入参 `billDate`、`kind`；每个账户独立调用。后台最近100条差异明细，其余差异通过告警核查。演示模式使用模拟数据，不访问微信或触发退款、提现。

协议参考：[微信账单产品介绍](https://pay.wechatpay.cn/doc/v3/merchant/4013071215)、[资金账单字段](https://pay.wechatpay.cn/doc/v3/merchant/4013071249)、[资金账单接口](https://pay.wechatpay.cn/doc/v3/merchant/4013421284)。

## 支付异常告警

包括支付下单失败、查单失败、回调验签/解密失败、回调订单不存在、支付金额/商户/交易号/时间校验失败、本地入账失败、账单差异和对账任务失败。告警记录只包含固定业务说明、订单号或任务日期，不保存支付密钥、下载令牌、回调密文或用户身份数据。

同一类型与目标合并计数、更新最近发生时间；再次发生会重新打开已处理告警。后台顶部每分钟读取待处理数量并提供入口；列表优先显示待处理告警，最多 100 条。读取失败显示失败状态，避免把未成功读取误认为没有告警。

管理员填写处理备注后标记已处理，对账执行和告警处理写入操作日志。本次告警渠道为运营后台，不发送短信、邮件或微信消息。

接口：`admin.payment.overview`、`admin.payment.alertCount`、`admin.payment.reconcile`（`billDate`）、`admin.payment.resolve`（`id`、`note`）。服务端和演示模式均检查超级管理员权限。

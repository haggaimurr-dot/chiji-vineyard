# 葡萄园下地与闯关原型

更新：2026-10-12。独立微信小游戏增加实际可玩的第三人称三维演示，人物可以在园区走动、靠近目标、长按干活并保存关卡进度。本轮实现两章，尚未交付八章完整游戏。

## 如何试玩

在仓库根目录执行 npm run game:build，再执行 npm run game:preview。浏览器打开 http://127.0.0.1:5199/field.html。旧版经营玩法仍可在 http://127.0.0.1:5199/ 试玩。

微信开发者工具导入 minigame 目录。默认 demo=true、experience=field 时启动新的下地体验；experience=classic 可进入旧版。关闭 demo 后当前仍使用已实现的第一版正式后端，三维关卡暂未接入正式服务。真实小游戏 AppID、微信设备运行与性能验收仍需完成。

## 已实现的玩法

- 四个内置人物：林禾、夏青、乔叔、陈雨。选择时预览实际三维人物，后续更换不清空农场。
- 第三人称跟随镜头、拖动画面旋转、摇杆和电脑方向键/WASD移动。围栏、树干、棚架和设施参与碰撞。
- 任务指南引导人物沿可行走路径到操作地点。移动到目标附近后才能干活，不会直接传送或远程完成农事。
- 第一章按七步完成：取苗、挖坑、栽植、绑支撑、到水源装水、回苗旁浇水、挂名牌。人物动作伴随土坑、苗木、支撑、湿土和名牌变化。
- 第二章明确进入已有成熟葡萄园，育苗角保留第一株幼苗。三批果实成熟程度不同，玩家判断采收、安排排水/避雨预算，并完成交货。
- 降雨在第 6 个行动时刻发生；第 7 时刻起批发行情下调；第 10 时刻为订单截止。界面提前展示这些条件，走动与现实等待不推进时钟。
- 固定订单收本季 A/B 级葡萄，以 18 公斤为通关目标；批发收各等级并按当前游戏报价结算。渠道选择展示数量、报价与预计收入。
- 第一章首次奖励 100，第二章首次奖励 250。后续成熟季销售自己新采的果实可以获得收入，通关奖励不会重复发放。
- 失败保留人物、幼苗、经营币、设施和库存，允许批发补救及明确进入下一成熟采收季。旧季库存不能充作本季新鲜订单。
- 独立本地存档、重载继续、损坏存档保留和确认重开。动作完成并保存成功才更新规则状态；中断长按不扣资源。离开游戏取消未完成动作，暂停挑战时间。

本原型中的糖度门槛、价格、损伤、工时和费用是教学游戏参数，尚未按实际园区和品种校准。人物与场景由程序生成，是可交互的临时三维资源，画面尚未达到之前概念图的美术质量。

## 技术与兼容范围

玩法规则位于 minigame/field/model.js，移动和路径位于 navigation.js，三维场景位于 world.js，界面位于 hud.js，持久化和输入适配位于 platform.js/main.js。

原型使用 Three.js 0.162.0，保留 WebGL 1 的运行路径以便适配微信 Canvas。浏览器使用三维画布与二维透明界面；微信构建产物将二维界面作为纹理叠加进同一 WebGL 画布，不依赖 DOM。依赖打包到 field/field-wechat.js，并保留 Three.js 许可。版本依据：[Three.js r162 WebGLRenderer 源码](https://github.com/mrdoob/three.js/blob/r162/src/renderers/WebGLRenderer.js)。

演示使用 chiji_vineyard_field_demo_v1 存档键，与已有 Canvas 第一版隔离。旧版后端、商城数据和正式存档不参与新关卡结算。正式关卡接入服务端时，还需实现事件种子、关卡版本、资源与订单事务结算及迁移。

## 验证与下一步

规则检查运行 npm run test:game-field；实际浏览器交互运行 npm run test:game-field-ui；无 DOM 的 WebGL / 微信输入适配模拟运行 npm run test:game-field-native。证据保存在 docs/test-evidence/2026-10-12-vineyard-field/。浏览器 WebGL 和模拟的微信输入环境不能代替微信开发者工具、安卓/iOS 真机验收。

下一步根据试玩反馈完善人物、农事动作与现场表现，然后逐步补幼树培养、萌芽防霜、高温管理及采后恢复。生产美术需要有骨骼的角色、经审核的葡萄植株模型、贴图与声音；正式运行还需要服务端关卡结算和手机性能验证。
